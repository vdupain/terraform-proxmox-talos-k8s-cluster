# ai-cluster — Operational Procedures

The `ai-cluster` is a single-node Talos Kubernetes cluster on `pve3` with an RTX 3060
passthrough, serving AI workloads (open-webui + ollama with qwen3.5 models).

**Energy-saving philosophy**: `pve3` is powered off by default. The cluster is started
on demand and shut down cleanly when unused.

Run the scripts from `examples/7-ai-cluster-single-node/` (kubeconfig and talosconfig
are generated by `terraform apply` into `output/`).

## Hardware / network

| Item | Value |
|---|---|
| Node | `pve3` (Proxmox host, powered off by default) |
| pve3 MAC (WoL) | `54:bf:64:6c:b8:53` |
| LAN broadcast | `192.168.10.255` |
| VM `ai-cluster-cp-0` | `192.168.10.203` |
| Cluster endpoint | `192.168.10.203` |
| Cilium LB pool | `192.168.10.230` – `192.168.10.235` |
| Domains | `*.ai.vincentdupain.com` |

## Startup (`ai-cluster-up.sh`)

1. **Wake-on-LAN** — sends a WoL magic packet to `pve3` (UDP broadcast, no Proxmox API).
2. **Ensure VM running** — short probe of the Talos apid port; if the VM does not answer, queries the Proxmox API and starts the VM explicitly (handles the case where pve3 is already up).
3. **Wait for boot** — polls the Talos apid port **50000** on `192.168.10.203` (default timeout 300s; Talos does not listen on SSH port 22).
4. **Verify Ready** — `kubectl wait --for=condition=Ready node --all`.

```bash
./ai-cluster-up.sh
```

Idempotent: safe to re-run. If the VM must be started via the API, set `AI_CLUSTER_VMID`, `PROXMOX_VE_ENDPOINT`, `PROXMOX_VE_API_TOKEN`.

## Shutdown (`ai-cluster-down.sh`)

Full power-off: VM stop then pve3 host shutdown.

1. **Cordon** — stop new workloads on the node (`ai-cluster-cp-0`).
2. **Drain** — evict running workloads safely (protects PVs and etcd).
3. **Talos shutdown** — ordered halt, powers off the VM.
4. **pve3 power-off** — Proxmox API `POST /nodes/pve3/status` (command=shutdown).

```bash
# Must run from a node that is NOT pve3 (pve0 online, or the Hermes host)
export PROXMOX_VE_ENDPOINT="https://pve0:8006"
export PROXMOX_VE_API_TOKEN="user@pam!token=secret"
./ai-cluster-down.sh
```

Idempotent: safe to re-run (skips if pve3 already stopped).

> **Execution context**: the homelab profile (Hermes) runs these scripts — it has Proxmox API access. The pve3 power-off is executed from a reachable node (pve0), never from pve3 itself.

Models live on the ZFS pool (`zfspv-pool` on the user disk, PV 15Gi).
To add more models, grow `user_disk_size` in `main.tf` (`autoexpand=on` picks it up).

## Troubleshooting

- **`up.sh` times out at "Verifying nodes Ready"** — after a full power-off cycle
  (pve3 was off), the K8s API may never come up: `/etc/kubernetes/manifests`
  is empty (race at boot when the VM starts via onboot before storage is ready).
  Fix: `talosctl --talosconfig output/talos-config.yaml --nodes 192.168.10.203 reboot`
  then re-run `./ai-cluster-up.sh`.
- **`ollama list` empty after startup** — check the open-webui HelmRelease has the
  `ollama.ollama.models` structure (double nesting, subchart v1.65.0) so the postStart
  hook pulls models.
- **GPU not detected** — check `kubectl get nodes -o json | jq '.items[0].status.capacity'`
  for `nvidia.com/gpu`; verify the PCI path `0000:b3:00.0` and `local-zfs` datastore in
  `main.tf`.
